# 03 · 环境现状与验收基线

## 本节目标

在改任何东西之前，先把「现在长什么样」拍下来。以后出问题，可以对比「改之前 / 改之后」。

做完你应得到：

- 一份 Windows `nvidia-smi` 文本
- 一份 WSL `nvidia-smi` 文本
- WSL 发行版与内核版本记录

---

## 为什么先做基线？

- 驱动更新、装 Docker、起 vLLM 都可能改变行为；没有基线就无法判断「是我改坏的，还是本来就这样」。
- 你已知驱动是 **552.12**、CUDA 兼容约 **12.4**——用命令再确认一次，避免口头信息与机器不一致。

---

## 前置条件

- 能登录 Windows：本机桌面 / RDP / 你自己的远程方式
- 能进入 WSL：在 Windows 里执行 `wsl -d Ubuntu-24.04`（发行版名以你机器为准）

---

## 操作步骤

### A. Windows：记录 GPU 与驱动

在 **PowerShell** 或 CMD 中执行：

```powershell
nvidia-smi
```

建议再记一份精简信息：

```powershell
nvidia-smi --query-gpu=name,driver_version,memory.total,memory.free --format=csv
```

**你要看什么：**

| 字段 | 期望（当前基线） |
|------|------------------|
| GPU Name | 类似 `NVIDIA RTX 6000 Ada Generation` |
| Driver Version | `552.12`（若已变，以机器为准） |
| CUDA Version（右上角） | 驱动宣称支持的最高 CUDA，约 12.x |
| Memory | 约 49140 MiB（48GB） |

把完整输出复制到记事本或本仓库临时笔记里（例如 `6000_server/notes/baseline-windows.txt`，可选）。

### B. WSL：记录同一张 GPU

进入 WSL 后：

```bash
# 确认发行版与版本
cat /etc/os-release | head -5
uname -r

# GPU 是否透传成功
nvidia-smi
```

**为什么 Windows 和 WSL 都要跑？**

- Windows 的 `nvidia-smi` 证明：**驱动装在宿主机上且正常**。
- WSL 的 `nvidia-smi` 证明：**WSL2 GPU 透传链路正常**（后面 Docker/vLLM 都依赖这条链路）。

两边驱动版本号应一致（或极接近）。若 WSL 里没有 `nvidia-smi` 或报错，先停在这里，不要更新驱动以外的软件栈。

### C.（可选）确认没有装「错误的」Linux 驱动包

在 WSL：

```bash
# 若输出很多 nvidia 内核模块相关包，要警惕；WSL 通常不应依赖 Linux 侧驱动
dpkg -l | grep -i nvidia | head -50
```

正常情况：可能看到少量用户态库；**不应**为了「补驱动」去 `apt install nvidia-driver-xxx`。

## 验收

全部满足再进入下一步：

- [ ] Windows `nvidia-smi` 有输出，卡名正确，显存约 48GB
- [ ] WSL `nvidia-smi` 有输出，驱动版本与 Windows 一致
- [ ] 已保存两份输出文本，便于对比

---

## 常见问题

**Q：WSL 里提示 `nvidia-smi: command not found`？**  
A：有时是 PATH 或发行版未正确挂载 GPU。先在 Windows 确认驱动正常，再 `wsl --shutdown` 后重开 WSL，再试。仍不行把完整报错留下再问。

**Q：两边驱动版本不一致？**  
A：少见。先 `wsl --shutdown`，重启 Windows 后再比。不要在 WSL 里装 Linux 驱动「对齐」。
