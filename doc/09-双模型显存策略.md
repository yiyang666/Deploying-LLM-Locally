## 本节目标

根据 **48GB 实测**，决定两个模型是：

- **A. 一次只驻留一个，按需切换**（本教程默认推荐）  
- **B. 尝试双开常驻**（仅当显存与延迟都余量充足）

写出你的最终策略，并（可选）留下切换脚本思路。

---

## 为什么不能想当然「两个都常驻」？

单卡显存大致被三块吃掉：

1. **权重（Weights）**：模型参数；FP8 / AWQ 已比 BF16 小很多  
2. **KV Cache**：与 **并发数 × 上下文长度** 强相关；拉长 `max-model-len` 时这里暴涨  
3. **框架开销**：CUDA context、激活临时区、碎片等  

两个服务各起一个 vLLM，等于两套权重 + 两套 KV 预留，很容易把 48GB 顶满甚至 OOM。

MoE（如 Coder 30B-A3B）**激活参数小**，但专家权重仍占盘占显存；不要用「只有 3B 激活」误判为「只占 3B 显存」。

---

## 用你在 07 里的数做决策

在只跑 **一个** 模型、业务可接受的 `max-model-len` 下，看 `nvidia-smi`：

```text
已用显存 U ≈ ______ MiB
总显存 T ≈ 49140 MiB
剩余 R = T - U
```

### 决策规则（实用版）

| 情况 | 建议 |
|------|------|
| 单模型已用 ≥ 约 35–40GB，且你还要较长上下文 / 多并发 | **策略 A：按需切换** |
| 单模型已用较低（例如 &lt; 20GB），且两模型之和 + KV 余量仍舒服 | 可小范围试 **策略 B**，失败立刻回 A |
| 不确定 | **默认 A**，稳定优先 |

**默认推荐：策略 A（按需切换）。**  
Agent 与 Coder 很少需要同一秒内同时满血推理；切换成本是「停容器 + 起另一容器」的一两分钟级（权重已在缓存时更快）。

## 策略 A：按需切换（推荐）

### 做法

1. 同一时间只保留一个 `vllm-*` 容器  
2. 端口都映射 `8000`（或统一反代到同一入口）  
3. 切换时：`docker stop` 旧的 → `docker run` 新的  

### 示例切换脚本思路

保存为 `~/bin/switch-llm.sh`（自行改模型名与镜像）：

```bash
#!/usr/bin/env bash
# 用法: switch-llm.sh agent|coder
set -euo pipefail

TARGET="${1:?用法: $0 agent|coder}"
IMAGE="${VLLM_IMAGE:?请 export VLLM_IMAGE}"
HF_CACHE="${HOME}/.cache/huggingface"

docker stop vllm-agent vllm-coder 2>/dev/null || true
docker rm vllm-agent vllm-coder 2>/dev/null || true

case "$TARGET" in
  agent)
    MODEL="${AGENT_MODEL:?}"
    NAME=vllm-agent
    SERVED=agent
    ;;
  coder)
    MODEL="${CODER_MODEL:?}"
    NAME=vllm-coder
    SERVED=coder
    ;;
  *)
    echo "未知目标: $TARGET"; exit 1
    ;;
esac

docker run -d --name "$NAME" \
  --gpus all --shm-size=8g -p 8000:8000 \
  -v "${HF_CACHE}:/root/.cache/huggingface" \
  "$IMAGE" \
  --model "$MODEL" \
  --served-model-name "$SERVED" \
  --host 0.0.0.0 --port 8000 \
  --max-model-len 32768 \
  --gpu-memory-utilization 0.90 \
  --trust-remote-code

echo "已切换到 $TARGET，日志: docker logs -f $NAME"
```

调用方（Agent 框架）始终访问 `http://127.0.0.1:8000/v1`，用 `model` 字段区分 `agent` / `coder`；切换后只保证「当前加载的那一个」可用。

## 策略 B：双开常驻（谨慎）

仅当你实测：

- 两个进程同时加载后仍有明显空闲显存  
- 各自 `max-model-len` 与并发被刻意限制  
- 延迟可接受  

做法示例：Agent 映射 `8000`，Coder 映射 `8001`，客户端按角色选端口。

**风险**：任一模型突发长上下文，可能拖垮另一服务或双双 OOM。

---

## FP8 vs AWQ（编程模型）怎么选？

| | FP8（官方） | AWQ（社区常见） |
|--|-------------|-----------------|
| 质量 | 通常更接近官方发布 | 视量化质量而定 |
| 显存 | 高于 4bit AWQ | 更省，利于单卡长上下文 |
| 兼容 | vLLM 对 Qwen 官方 FP8 路径清晰 | 依赖具体 AWQ 仓库与 vLLM 版本 |

48GB 上 **官方 FP8 单开通常够用**；若单开仍吃紧或要更长上下文，再试 AWQ。

## 常见问题

**Q：切换太慢？**  
A：保证 HF 缓存命中；不要每次删缓存；可考虑预拉两个模型文件，只停启容器。

**Q：想「热切换」零停机？**  
A：单卡 48GB 很难真正零停机双模型满配；需要第二张卡、或更小模型、或外部调度队列。
